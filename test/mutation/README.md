# 变异扫描

每条断言配一个它本该拦住的改动，注入 → 只跑那一条 → 还原，记录**咬 / 不咬**。

一条不会失败的断言比没有断言更糟：它让人以为这件事有人看着。

```bash
python3 test/mutation/run.py            # 全量
python3 test/mutation/run.py FocusRing  # 按测试名过滤
```

不进常规 `go test`——跑一遍要重复构建二十多次，属开发期工具。

## 加一条用例

往 `cases.json` 里加：

```json
{ "test": "断言名", "pkg": "./test/e2e/", "file": "被改的文件",
  "find": "锚点", "replace": "改成什么", "why": "这个变异代表什么危害",
  "all": false, "expect": "" }
```

- `all: true` —— 替换全部出现处。有些命题只有全改才成立（许可文本里 `MIT`
  出现两次，只改第一处断言仍能找到它，看起来像"不咬"其实是变异太弱）。
- `expect: "no-bite"` —— **哨兵**：这个变异**不该**触发该断言。只验"会咬"
  是不够的，一条什么都咬的断言同样没有信息量。

## 三条硬约束（都是栽过之后加的）

1. **注入前确认锚点命中**。找不到就报「注入失败」，**不能报成「断言不咬」**
   ——那会让人去弱化一条本来是好的断言。
2. **必须 `-count=1`**。e2e 在运行时 `go build`，测试缓存不知道 embed 资源变了。
3. **必须还原**。`finally` 保证异常退出也还原，跑完 `git status` 应当干净。

## 看到「不咬」时

**先怀疑变异，再怀疑断言。** 首轮 28 条里 7 条不咬，逐个追下去只有 1 条是断言
真的弱，其余 6 条是变异打在了断言从来没主张过的地方。判据：先读断言到底主张了
什么命题，再让变异去违反那个命题。
